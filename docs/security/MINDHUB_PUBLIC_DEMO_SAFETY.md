# MindHub 공개 데모 안전·개인정보 기준

> MindHub는 **의료기기도, 의료 서비스도 아니다.** 포트폴리오·연구용 비공개 검증 단계의 데모다.
> 이 문서는 공개 상태에서 지켜야 하는 안전선과, 그것이 코드 어디에서 강제되는지를 대응시킨다.

## 1. 제품 성격 고지 (필수)

- **진단·치료 도구가 아니다.** 역할은 기록 → 구조화 → 전달까지다. 진단명 단정, 약물 변경 지시,
  치료 권고를 생성하지 않는다.
- **의학적 판단은 의료진이 한다.** 리포트는 판단을 대체하지 않고 진료 전 참고 자료로만 제공된다.
- **공개 데모는 전부 가상 데이터다.** 실제 환자 데이터는 어떤 공개 경로에도 없다.
- **현재 일반 환자는 이용할 수 없다.** 환자용 기능은 지정된 테스트 계정 전용이다.
- **실제 의료정보를 입력하지 않는다.** 어떤 폼에도 환자 실명·진단명·진료기록을 넣지 않는다.
- **실제 도입 전 별도 검토가 필요하다.** 의료기관·법률·보안·개인정보 검토와 환자 동의 절차가 선행돼야 한다.

화면상 위치: `index.html`의 `#availability` 섹션(현재 공개 범위), `#proof`의 안전 목록,
리포트 푸터 고지, `doctor.html`의 "진단이나 응급 알림이 아니라" 고지, `app.html`의 이용 전 동의 화면.

## 2. 안전 기능은 AI 장애와 분리된다 (Non-negotiable)

위험 표현 감지는 **프론트엔드 규칙 기반**(`app.html`의 `RISK_WORDS`)으로 동작하며,
Solar·OpenAI·Supabase·네트워크 상태와 **무관하게** 항상 작동한다.

| 보장 | 구현 위치 | 검증 |
|---|---|---|
| 위험 감지가 네트워크에 의존하지 않음 | `RISK_WORDS`(app.html:592) + `isRisk()`(app.html:1161) — 순수 동기 문자열 검사, `fetch`/`await` 없음 | 코드 감사에서 확인. `sendMsg()`가 백엔드 호출 **전에** 동기 계산 |
| 백엔드가 죽어도 대화가 끊기지 않음 | `mockReply()` 로컬 폴백(app.html) | Solar 호출 실패·타임아웃 시 폴백 전환 확인 |
| 위기 자원 안내가 화면 안에서 제공됨 | 자살예방 상담전화 109 · 24시간 · 위급 시 112/119 | 브라우저 QA에서 데모 4단계 위기 카드 문구 실측 확인 |
| 백엔드가 위험 판정을 하지 않음 | `backend/server.js`의 `/chat` 주석 및 구현 — 추출은 `/extract`, 위험 감지는 프론트 담당으로 명시 분리 | 코드 감사 확인 |

**절대 금지**: 위험 감지를 LLM·서버 응답에 의존하게 바꾸는 변경. API가 죽으면 안전 기능도 죽는다.

## 3. 공개 경로는 실제 자원을 쓰지 않는다

| 경로 | 로그인 | Solar 호출 | DB 저장 | 검증 결과 |
|---|---|---|---|---|
| `index.html` 무로그인 데모 | 불필요 | 없음 | 없음 | **네트워크 요청 0건**(전부 로컬 스크립트) |
| `doctor.html?demo=1` | 불필요 | 없음 | 없음 | 발생 요청 전수 열거 결과 **CDN 라이브러리 1건뿐**, Supabase 프로젝트 API·Solar 백엔드 **0건** |
| `index.html` 도입 상담 | 불필요 | OpenAI(선택) | **DB 저장 없음** | 이메일로만 전달, 별도 DB 미저장 |
| `app.html` 환자 채팅 | **필수 + 승인 필요** | 있음 | 있음 | Origin + 로그인 + closed-beta 승인 3중 게이트 |

검증 상세: `docs/qa/MINDHUB_RECOVERY_QA.md` 5절.

## 4. 실제 환자 이용을 유도하지 않는다

- 환자 앱으로 가는 모든 링크는 **"비공개 테스트 로그인"** 으로 라벨링(3곳 전부, e2e 테스트로 고정).
- 최종 CTA에서 primary 강조는 **가상 데모**이고, 로그인 링크는 마지막 보조 CTA다.
- 신규 회원가입을 받지 않는다. 가입 폼 컨트롤은 CSS로 숨기는 게 아니라 **DOM에서 제거**했다.
- `#availability` 섹션이 "누구나 볼 수 있는 것"과 "지정 테스트 계정 전용"을 명시적으로 분리해 보여준다.

## 5. 접근 통제는 클라이언트만으로 하지 않는다

anon key는 **공개되도록 설계된 키**라 프론트 코드에서 숨길 수 없다. 따라서 프론트의 게이트는 UX 안내일 뿐이고,
실제 차단은 서버 측 3계층에서 이뤄진다:

1. **Supabase RLS** — `entries` INSERT/SELECT 정책에 `has_beta_access()` 조건.
   anon key로 REST API를 직접 두드려도 미승인 계정은 차단된다.
2. **백엔드 미들웨어** — `/chat`·`/extract`에 `requireAllowedOrigin → requireAuthenticatedUser →
   requireBetaAccess → rate limiter` 순서. `/chat`은 `entries`를 건드리지 않으므로 RLS만으로는
   미승인 계정의 과금 트래픽을 막을 수 없어 백엔드 게이트가 반드시 필요하다.
3. **프론트 안내** — `boot()`에서 `has_beta_access()` 재확인 후 권한 없으면 제한 안내 화면.

기본값은 **거부**다. `app_access_grants`에 행이 없거나 `status != 'approved'`면 접근 불가.
기존 사용자에게 자동 부여하지 않는다(마이그레이션이 전부 `pending`으로만 백필).

## 6. 개인정보 최소 수집

### 환자 경로
- 일반 대화 원문은 **기기(localStorage)에만** 두고 서버에 저장하지 않는다.
- 클라우드에 저장하는 것은 구조화된 신호(수면·복약·기분·스트레스원)와 안전 근거 원문뿐이다.
- 공유 범위는 환자가 결정하고, 그 결정은 **DB(RPC)에서 강제**된다 — 프론트 필터링에 의존하지 않는다.
- 의사 화면에는 미공유 필드가 `null`로, 일반 대화 원문은 **항상** `null`로 전달된다.
- **예외(의도적·고지됨)**: `red_flag=true`인 안전 근거 문장은 공유 토글과 무관하게 의사에게 전달된다.
  보호 목적이며 이용 전 동의 화면에서 명시적으로 고지한다.

### 기관 도입 상담 경로
- 수집: 기관명·기관유형·담당자명·업무용 이메일·연락처(선택)·도입목적·규모·희망일정(선택)·문의내용·동의 여부.
- **수집하지 않음**: 주민등록번호, 환자 실명, 진료기록, 의료영상, 처방전, 첨부파일 —
  입력 UI 자체가 없다(브라우저 QA에서 민감정보 요구 필드 0개 확인).
- 저장하지 않음: DB에 쓰지 않고 이메일로만 전달한다.
- 로그에 남기지 않음: 실패 시 사유·상태코드만 기록하고 문의 전문·이메일 주소는 남기지 않는다.
- 수신 주소는 코드에 하드코딩하지 않고 `ADOPTION_TO_EMAIL` 환경변수로만 관리한다.

## 7. 실패를 성공으로 위장하지 않는다

의료 인접 서비스에서 "보낸 것처럼 보이지만 안 보내진" 상태는 실제 위해로 이어질 수 있다.
그래서 다음을 원칙으로 강제한다:

- 메일 Secret이 없으면 **발송을 시도하지 않고 정직하게 실패**(503)를 반환한다. mock 성공을 반환하지 않는다.
- 프론트는 LLM 안내(폴백 있음)와 이메일 발송 결과(폴백 없음)를 **분리된 영역**에 표시한다.
  안내가 폴백으로 채워지더라도 발송 실패는 실패로 보인다.
- Solar 실패 시 임의의 분석 결과를 만들어내지 않고, 폴백임을 사용자에게 알린다.
- 브라우저 QA에서 실제로 실패 조건을 만들어 **거짓 성공 표시 0건**을 확인했다
  (`docs/qa/MINDHUB_RECOVERY_QA.md` 7절).

## 8. 시크릿 취급

- 프론트에 두는 것: Supabase **anon/publishable key**뿐(공개 설계, RLS가 보호).
- 프론트에 **절대** 두지 않는 것: `UPSTAGE_API_KEY`, `OPENAI_API_KEY`, `RESEND_API_KEY`,
  Supabase `service_role` key.
- 백엔드는 위 키를 환경변수에서만 읽고 하드코딩 폴백을 두지 않는다.
- 저장소에 커밋하지 않는다(`.gitignore`가 `.env` 차단, `.env.example`에는 이름만).
- 로그에 출력하지 않는다.
- **운영 서버가 저장소를 정적 서빙하지 않는다** — 감사에서 Render가 `.git`을 포함한 저장소 전체를
  노출하던 문제를 발견해 공개 파일 허용 목록으로 좁혔다(`backend/static-files.js`).

## 9. 실제 개인정보는 어떤 산출물에도 쓰지 않는다

- fixture·테스트·스크린샷·문서에 실제 이메일·UID·진료내용을 쓰지 않는다.
- 데모 환자는 "강하늘 (가상)"처럼 가상임을 라벨에 명시한다.
- 감사·QA 문서에는 사용자 수와 provider 종류 같은 **집계만** 기록한다.
- 조사 중 실제 사용자 세션을 발견한 경우 상태를 변경하지 않고, 식별 정보를 문서에 남기지 않는다.

## 10. 변경 시 회귀 방지 체크리스트

안전 관련 코드를 건드릴 때 반드시 확인:

- [ ] 위험 감지가 여전히 규칙 기반이고 네트워크에 의존하지 않는가
- [ ] Solar/백엔드/Supabase가 죽어도 대화·데모가 깨지지 않는가
- [ ] 위기 자원(109) 안내가 여전히 표시되는가
- [ ] 무로그인 데모가 여전히 실제 API·DB를 호출하지 않는가
- [ ] 미승인 계정이 `/chat`·`/extract`·`entries`에 접근할 수 없는가(3계층 모두)
- [ ] 의사 화면에 미공유 필드·일반 대화 원문이 전달되지 않는가
- [ ] 발송·저장 실패가 성공으로 표시되지 않는가
- [ ] 진단·치료 단정 문구가 추가되지 않았는가
- [ ] 시크릿이 프론트·로그·저장소에 들어가지 않았는가
- [ ] `npm run build`, `npm test`, `npm run test:e2e` 통과하는가
